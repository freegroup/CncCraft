Scripts and automation New in CncCraft

A small script drives CncCraft step by step – the visible mouse shows every click. Great for short videos for TikTok, Instagram and the like.

This is a pilot feature (beta). Scripting and the built-in automation server are new, still being refined and may change. They are meant mainly for recording demos; everyday work needs none of it.

CncCraft can run a script: a plain list of commands, one per line, that it carries out by moving the visible mouse and clicking the real buttons – so it looks exactly like someone using the program.

This is a nice way to build short demo videos for TikTok, Instagram or YouTube Shorts: the big visible cursor, the on-screen captions and the steady, repeatable moves make clean, hands-free clips. Record the window, set a title and a subtitle, pick the speed, and let the script draw and mill while the mouse shows every step.

The script window

Open it with Help ▸ Script…. It is its own window you can move anywhere. It has an editor with autocomplete and syntax highlighting, a Run and a Stop button, a Command help window listing every command, and an agent.md button that copies a full guide for an AI assistant.

How a script reads

  • One command per line, for example draw_rectangle cx=50 cy=50 width=40 height=30.
  • Write name = tool … to keep the result under a name, then use it later as $name.id – so you can draw a shape and give it a toolpath.
  • Lines like move_to, click, drag and type_text play through the visible cursor; screenshot, recording_start / recording_stop and window width=… height=… help with recording.
  • text_title and text_subtitle put a caption on screen, replay_speed sets how fast the mouse moves.

Snapping from a script

Every button has a command, so a script can switch the three snap methods (Snapping) on and off like any other: snap_to_geometry (bounding box), snap_to_center and snap_to_gap. That way a demo can show, step by step, how a shape lines up on an edge, a centre or an equal gap.

Automation server

Behind the scenes the same commands are an automation server running inside CncCraft on your own computer only (localhost). An AI assistant can connect to it and build a drawing for you while the visible mouse shows every move. Nothing leaves your machine.

All commands

These are every command a script (and the automation server) understands – the same set the AI assistant sees in agent.md.

Every line of a script is one of these commands. Parameters are written name=value; required ones are marked. Returns is what a later line can use through a variable (for example $name.id). This list is generated from the program itself, so it always matches your version.

agent_md

Get the agent guide (Markdown): what CncCraft and its script language are for, the syntax, coordinates and pacing rules, every command with its parameters and return value, and example scripts. Read it first to write scripts.

No parameters.

Returns: Text: the agent guide as Markdown.

No parameters.

Returns: JSON {"job": {"width", "height", "thickness", "material"}, "selection": [ids], "shapes": [{"id", "kind", "cx", "cy", "width", "height"}], "toolpaths": [{"index", "name", "tool", "cut_depth"}]}.

drag_shape

Drag a shape with the visible mouse: the cursor goes to the shape, presses, glides and releases so the top-left corner of the shape's outline box lands at (left, top). It is the app's own drag, so the shape snaps to the grid and to construction lines (and attaches to a line it lands on), as by hand. Returns {"id", "from", "to"}.

ParameterTypeRequiredValuesMeaning
idnumberyesThe shape's id (from a drawing tool's result or the state tool).
leftnumberyesWhere the left edge of the shape should end up, in mm from the left edge of the material.
topnumberyesWhere the top edge of the shape should end up, in mm from the bottom edge of the material.

Returns: JSON {"id", "from": {"left", "top"}, "to": {"left", "top"}} — the place asked for; the shape may snap a little to the grid or a construction line (read it back with state).

add_toolpath

Create a milling toolpath, all through the UI: the visible mouse clicks the shapes to select them (Shift for the extra ones), opens the milling panel if needed, clicks the operation's button, types the depths into the editor's fields when given, and clicks Anwenden. Fields left out keep the material's standard value. All shapes must be on screen (run view_fit first if needed).

ParameterTypeRequiredValuesMeaning
kindstringyesprofile, cutout, pocket, slot, drill, vcarveThe milling operation: profile (along the outline), cutout (cut the part free), pocket (clear the inside), slot, drill (holes) or vcarve.
shape_idsarrayyesThe ids of the shapes to cut (from a drawing tool's result or the state tool).
cut_depthstringnoHow deep the cut goes in total (the 'Zieltiefe' field): a number in mm or a variable/formula like platte_d or platte_d/2 (optional).
max_depth_per_passstringnoThe most the cutter takes per pass (the 'Zustellung' field, 'Bohrtiefe je Hub' for drilling): a number in mm or a formula (optional).

Returns: JSON {"kind", "shape_ids": [ids], "cut_depth", "max_depth_per_pass"} — the toolpath is computed once the mouse has clicked Anwenden; read it back with state.

An empty text removes it. It does not wait; add wait to hold the scene. Defaults: top centre, 40 pt, no time limit. Headline and subtitle are independent — both can show at once.

Start recording the window to an .mp4 video (H.264, encoded inside the app). Everything shown is captured, including the virtual mouse and captions. Stop it with recording_stop. Set the window size with window first, since the video keeps the size it starts with.

ParameterTypeRequiredValuesMeaning
